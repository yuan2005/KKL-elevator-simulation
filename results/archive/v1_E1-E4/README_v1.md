# KKL 电梯分场景控制策略仿真

COMP1110 Group 73。用 Python 仿真验证 Project Plan 的研究问题：在课表驱动、多入口的 KKL 里，客流参数达到什么条件时值得切换电梯调度组合。

> ⚠️ **目前所有参数都是占位值**（`config.py` 中标 [占位]），课表是合成的（`data/timetable_synthetic.csv`）。下面的结果是"方法跑通 + 初步结论"，实测数据替换后要重跑。

## 运行
需要 Python 3 + numpy、pandas、matplotlib、scipy（不需要 SimPy）。在 `project/` 目录下：

```
python3 -m simulation.experiments smoke   # 单个乘客手算核对
python3 -m simulation.experiments e0      # 与 Barney 往返时间公式比对
python3 -m simulation.experiments e1      # 6 个场景 × 7 个组合 × 30 次
python3 -m simulation.experiments e2      # 参数扫描 + 推导切换阈值（约 1 分钟）
python3 -m simulation.experiments e3      # 全天课表验证 + 节假日
python3 -m simulation.experiments e3b     # 人流放大 2–3 倍
python3 -m simulation.experiments e4      # 一台电梯停运
python3 -m simulation.experiments all     # 全部（约 3 分钟）
python3 -m simulation.plots               # 生成 results/figures/*.png
```
结果在 `results/*.csv`，图在 `results/figures/`。e3 会读取 e1、e2 的结果，所以要按顺序跑。

| `metrics.py` | AWT、P90、LWT%（>60 秒）、行程时间、运行距离、运行台时；配对 t 检验 |

## 模型要点
- **建筑**：LG3–16/F 共 20 层，层高 3.6 m；入口层 LG2 和 G；6 台客梯。
- **人流**：到达率、进楼/离楼/楼层间比例、楼层权重（课室在 LG1、1/F、2/F）、结伴到达（批量，Kuusinen 2012）；只差 1–2 层的人有一定概率走楼梯。
- **公平比较**：同一随机种子下各组合面对完全相同的乘客（相同随机数），用配对 t 检验判断显著性。
- **模型校验（E0）**：单入口上行高峰下，仿真往返时间与 Barney 解析公式平均只差 **0.5%**。

## 策略组合
| 代号 | 组合 | 文献 |
|---|---|---|
| C0 | 最近车，分配后不改派，无停靠，无满载直驶（现状基线） | Plan 1.2 观察 |
| C1 | ETA 分配 + 顺路加分 + 分散停靠 + 满载直驶 | Peters 2014 |
| C2 | 上行分区（按"人数×距离"均衡）+ 入口层停靠 | So, Yu & Chan 1999；Al-Sharif 2018 |
| C3 | 下行分区 + 分区顶层停靠 | Barney 2003；Otis US5480006 |
| C4 | 简化 RSR 评分 + 分散停靠 | Bittar 1982 |
| C5 | 只开 2 台 + G 层停靠（节能） | de Almeida 2012；EMSD |
| C6 | ETA + 课表预测停靠（下课前把空梯调到将下课的楼层） | Brand & Nikovski 2004 |
| C7 | ETA + 入口层停靠（不分区，对照 C2） | Peters 2014 §5.1 |

## 初步结果（占位参数下）
**E1 各场景平均等待时间（秒，30 次平均）**

| 组合 | S1 课前 | S2 课后 | S3 换课 | S4 饭点 | S5 平时 | S6 假日 |
|---|---|---|---|---|---|---|
| C0 现状基线 | 20.7 | 22.1 | 17.1 | 12.5 | 10.4 | 8.7 |
| C1 ETA | 12.5 | **13.1** | **14.5** | **8.8** | **6.8** | **5.5** |
| C4 RSR | 12.2 | 13.5 | 15.1 | 9.1 | 6.9 | 5.5 |
| C7 ETA+入口停靠 | **10.4** | 15.3 | 15.4 | 12.1 | 12.8 | 12.8 |
| C2 上行分区 | 13.6 | 15.5 | 17.5 | 13.1 | 13.1 | 13.0 |
| C3 下行分区 | 17.0 | 20.0 | 21.4 | 14.9 | 12.1 | 12.9 |

**E2 推导出的切换规则**（`results/e2_rules.json`、图 `e2_floormix_threshold.png`）
1. 进楼乘客占 ≥ 90% 时（课前进楼），从 C1 切到 **C7 入口层停靠**。
2. 上行分区 C2 **只在重上行高峰且去高层的人多时**才显著更好，例如：
   - 去 5/F 以上比例 ≥ 71%：每 5 分钟 ≥ 200 人
   - 去 5/F 以上比例 ≥ 57%：每 5 分钟 ≥ 250 人
   - 去 5/F 以上比例 ≥ 51%：每 5 分钟 ≥ 300 人
   - 在楼层均匀的标准办公楼里，C2 可把近饱和时的平均等待降低约 40%，复现了文献结论；但 KKL 课室集中在低层，这个收益消失。
3. 下行分区 C3 在所有测试条件下都**不比 ETA 好**。
4. 每 5 分钟 ≤ 25 人时，可以切到 **C5 节能模式**：平均等待从约 6 秒升到 11–23 秒。节假日全天测试中，运行台时从 66 降到 22（−67%），平均等待从 5.4 秒升到 13.9 秒。

**E3/E3b 全天验证**
- 相对现状基线 C0，任何一种现代组合都能把全天平均等待降低约 40%（14.6 → 8.7 秒），长等待（>60 秒）基本消失。
- 在合成课表（最忙的 5 分钟约 110–134 人）下，"按课表预切换"和"阈值实时切换"**都没有比最好的单一组合 C1 显著更好**；把人流放大到 2–3 倍仍然如此。原因是 KKL 的需求达不到第 2 条的分区阈值。
- 出席率 ±20% 的误差不改变上述结论。

**E4**：一台电梯停运时，C1/C4 仍明显优于现状基线。

> 报告可以这样表述：对 KKL 来说，主要收益来自"把现状调度换成 ETA 类算法"和"课前改为入口层停靠"；分区类策略只有在高层需求大、接近饱和时才值得切换。阈值表给出了这个边界。这正符合 Plan 2.3 的写法："若没有找到可靠阈值，就如实报告"。

## 已知局限
- 参数和课表都是占位/合成数据；出席率、电梯使用率、楼梯分流概率都是假设。
- 不模拟乘客看到排队后改主意（例如中途改走楼梯）；不模拟目的层调度硬件。
- 能耗只用运行距离和运行台时做近似，没有电机功率模型。
- 固定步长 0.25 秒，时间误差不超过一个步长（smoke 测试已核对）。
