## 运行
需要 Python 3（3.10 及以上）。先安装依赖：

```
pip install -r requirements.txt
```

然后**在本文件夹（仓库根目录）里**运行：

```
python3 experiments.py smoke   # 单个乘客手算核对
python3 experiments.py e0      # 模型校验（约 5 秒）
python3 experiments.py e1      # 策略地图（约 6 分钟，3 万次仿真）
python3 experiments.py e2      # 全天验证（约 2.5 分钟，需先跑 e1）
python3 experiments.py e3      # 一台电梯停运（约 30 秒，需先跑 e1）
python3 experiments.py all     # 全部
python3 plots.py               # 生成 results/figures/*.png
```

可选参数：`--seeds N` 每种情况的重复次数（默认 10）；`--points N` E1 的抽样点数（默认 500）。
仓库里已经带有一份完整结果（`results/`），不重跑也能直接看。

## 人流模型
四类乘客：

| 类型 | 起点 → 终点 | 说明 |
|---|---|---|
| 进楼 | 入口层（LG2/G）→ 楼内 | 入口层比例 LG2 40% / G 60%（占位） |
| 离楼 | 楼内 → 入口层 | |
| 楼层间 | 楼内 → 楼内 | |
| **过路** | **LG2 ↔ G，不进楼** | 例如从大学道去天桥/庄月明文娱中心方向。**默认占乘电梯人数的 30%**（占位假设），上下行各半 |

- **场景模式**（E1）：每个点给定人数、非过路乘客的进/离/楼层间比例、过路比例、楼层分布（低层课室集中 ↔ 各层均匀）。
- **全天课表模式**（E2/E3）：课表驱动的上下课人流 + 背景人流（办公、饭点等）+ 过路人流。过路人流的时间分布跟随楼内其他人流（上下课、饭点时多）。
- 只差 1–2 层的非过路乘客有一定概率走楼梯；过路比例按"乘电梯的过路者"定义，不再做楼梯分流。

### 地图用到的人流参数（全部可由人流摄像头 / 呼梯记录统计）
每 5 分钟乘梯人数、进楼比例、离楼比例、过路比例、**从入口层出发比例**（= 进楼 + 过路）、**去入口层比例**（= 离楼 + 过路）、进楼乘客去 5/F 以上的比例。

## 策略组合
| 代号 | 组合 | 文献 |
|---|---|---|
| C0 | 最近车，分配后不改派，无停靠，无满载直驶（现状基线，只作参照） | Plan 1.2 观察 |
| C1 | ETA 分配 + 顺路加分 + 分散停靠 + 满载直驶 | Peters 2014 |
| C2 | 上行分区（按"人数×距离"均衡；过路乘客不分区）+ 入口层停靠 | So, Yu & Chan 1999；Al-Sharif 2018 |
| C3 | 下行分区 + 分区顶层停靠 | Barney 2003；Otis US5480006 |
| C4 | 简化 RSR 评分（多呼梯、较满的车扣分）+ 分散停靠 | Bittar 1982 |
| C6 | ETA + 课表预测停靠（只用于"按时段名称切换"反例） | Brand & Nikovski 2004 |
| C7 | ETA + 入口层停靠 | Peters 2014 §5.1 |

（原 C5"只开 2 台"的节能组合已删除。）

## 结果
### E0 模型校验
- 仿真往返时间与 Barney 公式平均只差 **0.5%**。
- 标准办公楼（单入口、各层均匀、无过路）的重上行高峰下，上行分区让平均等待减少 **36–52%**，复现了文献结论。

### E1 策略地图
**怎么判"最优"**：每个点在 C1/C2/C3/C4/C7 里选平均等待最短的；**只有显著好过 C1（配对 t 检验 p<0.05）才换**，否则留在 C1（没把握就不换）。决策树深度用 5 折交叉验证的"后悔值"（相对每点最优组合多等的秒数）选择，后悔值比最小值多不到 3% 时取最简单的树。

**地图规则**（`results/e1_rules.txt`，深度 3，实质上只有一条）：
> **从入口层出发的比例 > 0.76，且每 5 分钟乘梯 28–125 人 → 用 C7 入口层停靠；其他 → C1。**

| | 平均后悔（秒） |
|---|---|
| 查地图 | 0.18 |
| 一直用 C1 | 0.25 |
| 一直用 C0（现状） | 6.06 |

- **过路乘客的影响**：C7 的适用条件取决于"在入口层叫电梯的人"占多少，而进楼和过路乘客都是在入口层叫电梯的。单看进楼比例时信号会被过路乘客稀释（第一次拟合只用进楼比例，地图退化成"永远 C1"）。加入"从入口层出发比例"后规律很清楚：这个比例低于 0.7 时 C7 都比 C1 差，0.7–0.8 时持平，高于 0.8 时 C7 中位数少等约 6%，高于 0.9 时少等约 9%。
- **S1 课前进楼**（过路 30%）：从入口层出发比例 0.86，地图选 C7，平均等待从 11.6 秒降到 8.4 秒（−27%）。其余代表点都选 C1。
- **地图没画出、但数据里存在的次要区域**（点太少）：
  - C2 上行分区：每 5 分钟 > 220 人、进楼为主时，4 个点胜出，平均少等 9.3 秒。
  - C4 RSR：接近饱和、楼层间移动多时，11 个点胜出，平均少等 2.5 秒。
  - 在这类接近饱和的人流下，C1 有时甚至不如现状 C0（见 `e1_strategy_map.png` 右下）。
- 500 个点里，C1 是最优的有 454 个，C7 有 30 个。

### E2 全天验证（每种情况 10 天；课表预测始终按出席率 0.8、过路 30%）
**① 只看切换生效的时段**（同一批乘客，对比"一直用 C1"；图 `e2_switch_periods.png`）

| 情况 | 课表预测 + 地图 → C7 | 地图实时 → C7 | 按时段名称切换 → C7 |
|---|---|---|---|
| 出席 0.64 / 过路 30% | **−14.5%** | **−9.2%** | +4.1%（变差） |
| 出席 0.8 / 过路 30% | **−13.6%** | **−8.4%** | +2.0% |
| 出席 0.96 / 过路 30% | **−12.8%** | **−7.2%** | +1.6% |
| 出席 1.6 / 过路 30% | **−5.5%** | +1.1% | +4.4%（变差） |
| 出席 2.4 / 过路 30% | **−4.9%** | −4.2% | −0.6% |
| 出席 0.8 / **过路 10%** | **−7.3%** | **−5.8%** | **+12.3%（变差）** |
| 出席 0.8 / **过路 50%** | **−16.8%** | **−7.3%** | −1.0% |

粗体数字 p<0.05；"（变差）"表示显著变差。

- **用课表预测人流参数再查地图，在所有 7 种情况下都显著减少等待**，包括实际过路比例与预测的 30% 不同（10% 或 50%）的情况。
- 只看过去 5 分钟的实时切换也有效，但人很多时（出席 1.6）会因滞后而失效。
- 按"上课时间"这个名称直接切换，有时显著变差。**切换应依据人流参数，而不是时段名称。**
- 过路比例越高，C7 的收益越大（过路 10% 时 −7.3%，50% 时 −16.8%），因为在入口层叫电梯的人更多。

**② 全天平均**：
- 相对现状 C0，ETA 类控制把全天平均等待从 14–47 秒降到 9–24 秒，降幅约 38–50%。
- 切换的全天平均改善较小（课表预测 + 地图比静态 C1 少 0.08–0.20 秒，多数情况显著），因为需要切换的时段每天只有约 600–1,400 人次。

### E3 一台电梯停运（地图仍按 6 台训练）
- C1 类控制仍比现状 C0 少等约 37–43%。
- 课表预测 + 地图在出席 0.8 时，切换时段仍少等 **8.3%**（显著）；出席 1.6 时少等 1.3%（不显著）。

## 报告可以怎么写
1. **最大的收益来自把现状调度换成 ETA 类算法**：等待减少约 38–50%。
2. **切换规则可以用可观测的人流参数表达**（策略地图）。对 KKL：**当在入口层叫电梯的人（进楼 + 过路）超过约 3/4，且每 5 分钟 28–125 人时，让空梯回入口层待命**；其余时间用 ETA。分区只在"人很多且进楼为主"时才值得。
3. **用课表预测这些参数并提前切换**，能在切换时段显著减少 5–17% 等待，并且对出席率和过路比例的估计误差稳健；按时段名称切换则不可靠。
4. **LG2↔G 的过路人流会让入口层停靠更有价值**，所以实地测出过路比例很重要。

## 已知局限
- 参数和课表都是占位 / 合成数据；出席率、楼梯分流概率、过路比例和方向都是假设。
- 地图的 500 个点各做一次 p<0.05 检验，少数"胜出"可能是偶然显著（预计约 5% 的误报），这也是只采用简单规则的原因之一。
- 不模拟乘客看到排队后改主意；不模拟目的层调度硬件。
- 固定步长 0.25 秒，时间误差不超过一个步长。
